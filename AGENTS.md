# mic-dsp

A personal, always-on macOS virtual mic. The owner's SM7dB goes into a Komplete Audio 1, a Rust daemon runs it through a vocal chain, and the result goes to a BlackHole-based virtual input that any app can select. It has one user and one machine (MacBook Pro M4 Pro, macOS 26). The repo is public on GitHub, but nothing built from it is published. How it works and why is in `docs/design.md`; read it before changing the DSP or the audio plumbing.

## Constraints

- Memory footprint under 10 MB and flat over 24 h. Measure it with `footprint <pid>`, not RSS.
- CPU under 1% of one core while active, about 100 µs per 10 ms frame for the whole chain, and zero while no app reads the mic.
- No GUI. The input gain is one number in `config.toml`, and nothing else needs tuning. The daemon survives replugging, sleep/wake and coreaudiod restarts.
- The audio callback does no allocation, locking, system calls, logging or I/O. Enable `assert_no_alloc` in debug builds.
  - Hand state in and out without blocking, and drop old state on the control thread.
  - Core Audio listeners only signal; all rebuilding happens on the control thread.
- DSP lives in a crate with no platform dependencies, so it runs offline.
  - Every stage is a struct with `process(&mut self, buf: &mut [f32])` and `set_params`.
  - Prefer hand-written DSP to new dependencies.
- The drivers (Francisco's Mic and Francisco's Speakers) are two builds of BlackHole configured through build flags only. BlackHole is GPL-3.0: keep its license next to any of its source in the repo, and never publish built binaries.
- The Mac plays through the owner's Multi-Output Device (the Komplete and Francisco's Speakers), not through micd. micd reads the loopback of Francisco's Speakers as the echo canceller's reference, only while an app reads the mic, and never writes to the Komplete's output.
- The repo is public, so never commit the owner's voice recordings. They live in `recordings/`, which is gitignored. Committed test fixtures are synthetic or generated by the tests.

## Verify

- `cargo test` and `cargo clippy --all-targets`.
- Prove a DSP change on audio: process a WAV with the offline mode and check levels and noise floor. Prove a live change by recording the virtual mic.

## Ask first

The owner may be on a call. Ask before:
- installing the driver, running `sudo` or restarting coreaudiod
- loading the LaunchAgent
- resetting TCC permissions
- changing the sample rate or the default devices
